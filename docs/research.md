# 同类产品调研

> 调研目的：确定 Dounai 悬浮窗在交互范式、系统集成深度与形态边界上的参考坐标，
> 并据此推导本层的设计取舍。调研时间：2026-10。
>
> **信息来源说明**：本机联网检索通道在本次会话中不可用（搜索 API 鉴权失败），
> 因此以下结论来自公开产品的既有资料与长期观察，**未做实时页面抓取**。
> 凡涉及具体版本号、性能数字的表述均标注为「定性」；本层的实测数据只来自
> `docs/selection-report.md` 中对 Electron/Tauri 的自建基准，两者不混用。

## 1. 参考产品

### 1.1 VPet（虚拟桌宠模拟器）

- **形态**：Windows 桌面宠物，常驻窗口 + 托盘，带养成系统。
- **技术路线**：C# / WPF，直接使用 Windows 原生窗口能力。
- **可借鉴**：
  - 托盘菜单承载「设置/隐藏/退出」这类低频操作，主窗口只放高频交互，避免悬浮窗塞满按钮；
  - 拖拽吸附边缘、置顶与「穿透点击」是桌宠类产品的标配期待；
  - 宠物本体与养成逻辑分离，本体只负责表现。
- **不照搬**：养成/数值系统不是本期需求，且会把组装层与业务逻辑耦合。

### 1.2 Shimeji-ee

- **形态**：跨平台（Java/Swing）桌面吉祥物，多实例、可爬窗口边缘。
- **可借鉴**：
  - 「形象 = 一组精灵图 + 行为脚本」的分离方式，与本期「形象渲染层可替换」目标一致；
  - 多实例与物理行为（掉落、攀爬）属于表现层，不应进入事件编排。
- **不照搬**：Java/Swing 的透明窗口在各平台表现差异大，且体积与启动不占优。

### 1.3 N0va Desktop（米哈游）

- **形态**：桌面壁纸/看板娘，强调高质量形象与低打扰。
- **可借鉴**：
  - 「默认静默、需要时才响应」的克制感——这正是本产品「默认态 logo 静默悬浮」的基调；
  - 形象资源与渲染管线分离，便于后续替换正式形象。
- **不照搬**：以视觉资产为核心，交互深度浅；本产品需要承载完整对话链路。

### 1.4 Desktop Goose

- **形态**：极简单一形象 + 强打扰式互动（拖文件、弹窗）。
- **可借鉴**：
  - 单一形象的「性格化动作」比复杂 UI 更能建立陪伴感；
  - 快捷唤起 + 轻量反馈的组合足够形成记忆点。
- **不照搬**：强打扰与本产品「勿扰模式」「不打扰也不缺席」的定位相反。
  Desktop Goose 恰好是「没有勿扰开关」的反面案例，佐证了勿扰模式的必要性。

### 1.5 豆包桌面端

- **形态**：AI 助手桌面客户端，悬浮球 + 主窗口双形态。
- **可借鉴**：
  - 悬浮球是「低占用入口」，主窗口承载完整对话——两级信息架构清晰；
  - 快捷键唤起、划词/截图等系统级入口是桌面 AI 产品的差异化来源。
- **不照搬**：其主窗口是重 UI；本产品本期只有悬浮窗，需要把对话压缩进小窗，
  因此流式文本必须能「就地展开/收起」，不能依赖跳转。

### 1.6 Raycast

- **形态**：macOS 启动器，命令面板 + 扩展生态。
- **可借鉴**：
  - 全局热键唤起的响应速度是体验核心（要求「按下即出现」，不允许有可感知延迟）；
  - 命令式交互（输入即搜索）比层层菜单高效。
- **不照搬**：键盘优先范式不适合「陪伴」场景，本产品以语音/文字对话为主。

### 1.7 uTools

- **形态**：跨平台效率工具，插件化，快捷唤起。
- **可借鉴**：
  - 插件/扩展的注册与生命周期管理，可映射到本产品的「形象渲染器注册表」；
  - 常驻托盘 + 热键唤起的最小系统集成集合。
- **不照搬**：插件市场与沙箱机制超出本期范围。

## 3. 推导出的设计结论

1. **悬浮窗只放高频交互**：对话流 + 一个输入入口；设置、退出、勿扰开关全部进托盘菜单
   （借鉴 VPet/uTools 的职责划分）。
2. **默认态必须「安静」**：无动画或极低幅度呼吸，符合 N0va 的克制基调，
   也避免长期驻留时的视觉疲劳与 GPU 占用。
3. **勿扰模式是硬需求而非可选项**：Desktop Goose 的反例说明，缺少一键静默的桌宠
   会被用户直接卸载。
4. **快捷唤起必须「即时」**：借鉴 Raycast，热键到窗口可见不应有可感知延迟；
   因此窗口常驻（不销毁重建），唤起只是 `show + focus`。
5. **形象层必须独立**：Shimeji 的「精灵 + 行为脚本」与 N0va 的「资源 + 管线」都证明，
   形象是易变资产，编排是稳定逻辑，二者不能混在一起。
6. **对话要能在小窗内就地完成**：借鉴豆包，但本产品无主窗口，所以流式文本区域
   需要支持「展开/收起」与「滚动跟随」，且不能因展开动画导致布局抖动。

## 4. 差异化定位

现有产品要么偏「宠物/玩具」（VPet、Shimeji、Goose），要么偏「效率工具」（Raycast、uTools），
要么偏「重客户端」（豆包桌面端）。Dounai 的差异点是：

> **以陪伴为主形态，但把技术控制权（模型、密钥、记忆、数据）完整交给用户。**

这决定了本层不能是「聊天框套壳」：它必须让用户在不打开任何设置页的情况下，
一眼看出当前是否有模块不可用（降级可视），并且所有数据都留在本机。
