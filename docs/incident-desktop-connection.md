# 重要公告：桌面端曾无法连接上游服务（已修复）

> **一句话**：2026-10-24 至 2026-10-26 期间的桌面版有个严重缺陷——能启动、有界面，
> 但**所有对话请求都失败**，界面显示「服务未连接」。已在 `3623a02` 修复。
> 如果你下载过这期间的版本，请重新克隆或重新打包。

---

## 1. 谁受影响

**受影响**：在 `0edb817` 到 `b5ac25b` 之间构建过桌面应用（`dounai.exe`）的用户。

**不受影响**：

- 只用 `npm run dev`（浏览器开发模式）的用户；
- 只读过源码、未打包桌面版的用户；
- 更新到 `4af37b8` 及之后版本的用户。

## 2. 具体现象是什么

桌面应用（`dounai.exe`）双击能启动，悬浮窗正常显示、logo 也在，但：

- 界面一直挂着「服务未连接」或「模型服务未连接」的徽标；
- 输入框是灰的、发不出消息；
- 即使三个上游（`8101` / `8102` / `8103`）都确认在运行，情况也一样；
- **同一个版本用 `npm run dev` 打开却完全正常**。

这个「dev 正常、打包后不正常」的差异，是判断自己是否中招的最好特征。

## 3. 为什么会这样

Dounai 的架构要求所有上游请求都经 **Rust 主进程代理**转发
（原因见 [`cors-and-proxy.md`](cors-and-proxy.md)：三个上游都不给浏览器跨域开口子）。
前端靠 `window.__TAURI__` 判断自己是否在桌面端，以此决定走代理还是直连。

这里有**两个缺陷叠加**：

| 缺陷 | 说明 |
|---|---|
| `tauri.conf.json` 没开 `withGlobalTauri` | 该字段默认 `false`，所以 `window.__TAURI__` 从未被注入到页面里 |
| 前端读的是 Tauri 1 的 API 结构 | Tauri 2 把 `invoke` 放在 `__TAURI__.core.invoke`，而代码取的是 `__TAURI__.invoke` |

结果：前端判断「这里没有 Tauri」→ 退回**浏览器直连**→ 被上游的跨域策略拦截：

- 输入层、模型层：请求到达了，但响应没有跨域许可头，浏览器**丢弃响应**；
- 语音层：直接返回 **403**（它有严格的来源白名单）。

所以现象很像「服务没起来」，但实际上是**前端根本没拿到响应**。

**同根因的连带影响**：托盘「勿扰模式」从前端传来的事件、面板展开时的窗口尺寸联动，
在那段时间里也都是失效的。修复后一并恢复。

## 4. 我们为什么会漏掉（不回避）

这一点必须写清楚，因为它决定了以后怎么防。

我当时的验证方法是：看到上游日志里出现了一条 `/v1/healthz` 记录、状态 200，
就判定「前端已经通过代理连上了上游」。

**这个推断是错的。** 直连模式下请求同样会到达服务端——跨域拦截发生在浏览器
**读取响应**的那一刻，而不是发送的那一刻。我只验证了「请求发出去了」，
没有验证「响应被接受了」。

这个错误的结论还进了测试报告，等于把一次未完成的验证记录成了通过。
本轮已更正：见 [测试报告 §6.6](TEST_REPORT.md)，那里保留了两版结论的对照，
不做粉饰。

## 5. 修复了什么

| 提交 | 内容 |
|---|---|
| `4af37b8` | 合并外部贡献者 [@Tonyjh07](https://github.com/Tonyjh07) 的 PR #1：开启 `withGlobalTauri`；`invoke` 改为 `__TAURI__.core?.invoke ?? __TAURI__.invoke`（兼容两代结构） |
| `3623a02` | 补 10 项环境探测回归测试；统一 `detectRuntime()` 与 `transportMode()` 的判定口径；更正测试报告中的错误结论 |

**修复后的实测结果**（真实桌面应用、三个上游在线）：

```text
transportMode = proxy          ← 走主进程代理了
probe         = input ✔  llm ✔  output ✔
turn          = state=talking, 文本 192 字, 有音频, 未降级
```

完整对话链路（输入 → 模型 → 语音 → 上屏）在桌面端可以正常工作。

## 6. 你需要做什么

**如果你只是使用、没有自己打包**：

```powershell
# 不在仓库里时，先重新克隆（或 git pull）
git pull
npm install
npm run build
npx tauri build --no-bundle
```

**如果你在用旧的可执行文件**：直接删掉旧的 `dounai.exe`，按上面重新打包。

**怎么确认已经好了**：新版本启动后，徽标应该消失、输入框可用；
发一句话应该能看到文字逐字出现，并且有语音。

## 7. 我们加了什么防止复发

1. **回归测试**：`tests/transport-mode.test.ts` 覆盖 Tauri 2 结构、Tauri 1 兼容、
   `__TAURI__` 存在但取不到 invoke 的中间态等 10 种情况。
   已验证它真的能守住：同一批用例在修复前失败、修复后通过。
2. **口径统一**：运行模式判定只保留一个真相来源，避免两处判定打架。
3. **验证方法修正**：以后验证「连通性」必须确认**客户端接受了响应**，
   而不是只看服务端有没有收到请求。这条已写进测试报告的教训记录。

## 8. 一点说明

这个缺陷在产品早期、且只在桌面端、且只在打包后出现，三个条件叠加让它藏得比较深。
但它确实存在了约两天，期间构建的桌面版不可用。这不是「小问题」，
我们在文档里按严重问题记录，没有降低描述。

如果你在那段时间里试过桌面版、并且以为是自己的模型配置有问题——
那不是你的配置问题，是我们的 bug。
