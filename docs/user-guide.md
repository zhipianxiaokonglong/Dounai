# 用户文档 · Dounai 桌面悬浮窗

> 这是 Dounai（开源 AI 情感助手）的桌面悬浮窗组件。它把输入、模型、语音三个模块
> 组装成一个可以常驻桌面的小伙伴。

---

## 1. 它是什么

一个无边框、常驻桌面、可以随时唤起的悬浮窗。默认形象是 Dounai 的 logo。
后续产品会推出正式助手形象，届时只需替换形象渲染层，其他一切不变。

它**自己不做**听写、不做模型推理、不做语音合成——这些分别由
输入层、模型层、语音层负责。悬浮窗负责把它们串起来，并让你看得见、听得着。

---

## 2. 快速开始

### 2.1 你需要先准备三件事

悬浮窗是「组装层」，它需要三个本地服务在跑。请先按各模块自己的文档启动：

| 模块 | 仓库 | 本项目默认端口 |
|---|---|---|
| 输入层 | [`Dounai_input`](https://github.com/zhipianxiaokonglong/Dounai_input) | `8101` |
| 模型层 | [`OmniNexus`](https://github.com/zhipianxiaokonglong/OmniNexus) | `8102` |
| 语音层 | [`MoodVoice`](https://github.com/zhipianxiaokonglong/MoodVoice) | `8103` |

> ⚠️ 注意：输入层与模型层的**出厂默认端口都是 8000**，同机运行必须错开。
> 本项目默认用 8101/8102/8103，你需要让上游也用这些端口，或在本项目设置里改。

以输入层为例（PowerShell）：

```powershell
$env:DOUNAI_DATA_DIR = "$PWD\.data"
$env:DOUNAI_PORT = "8101"
dounai-input serve
```

模型层（需要离线诊断模型时启用 `echo`）：

```powershell
$env:OMNI_PORT = "8102"
python -m omninexus
```

语音层：

```powershell
$env:EMOTION_TTS_PORT = "8103"
python -m emotional_tts serve
```

### 2.2 启动悬浮窗

安装包安装后直接运行 **Dounai**。首次启动时：

- logo 会静默悬浮在桌面右下附近；
- 点击 logo 展开对话面板；
- 如果某个上游没起来，窗体会自动显示一个小徽标告诉你**是哪一个**没连上。

## 3. 四种状态

| 状态 | 你会看到什么 | 什么时候出现 |
|---|---|---|
| 静默 | logo 轻微呼吸，不打扰 | 启动后、每轮对话结束 |
| 唤醒 | logo 放大、光晕亮起 | 收到唤醒事件、按唤起热键 |
| 对话 | 文字逐字出现 + 语音播放 | 你发消息之后 |
| 情感（预留） | — | 后续接入正式形象后启用 |

**情感表现层本期不启用**，但状态位已经预留：编排器会把模型返回的
`emotion` 标签记录下来，形象层也有 `setEmotion()` 接口，等正式形象到位即可生效。

---

## 4. 怎么说话

面板底部有三个入口，对应三种输入方式：

| 入口 | 操作 | 说明 |
|---|---|---|
| 文字 | 在输入框打字，回车发送 | 最直接 |
| 图像 | 点 🖼 选一张图 | PNG / JPEG / WebP / GIF，≤ 15MB |
| 语音 | 点 🎙 开始录音，再点一次结束 | 录完自动上传并转写 |

**关于语音**：录音以 WebM 上传给输入层，由它转写成文字后送给模型。
如果输入层没配置转写能力（例如只跑离线直通），语音事件仍会生成，但转写结果为空，
界面会提示「语音转写不可用」。这时改用文字即可。

**关于唤醒**：如果你在输入层启用了声纹唤醒，说唤醒词后悬浮窗会先进入唤醒态
（logo 放大、光晕亮起），再进入对话态。

### 4.1 切换人格 / 提示词

面板顶部有一个下拉框，列出模型层提供的提示词配置（默认只有 `default`）。
切换后**下一轮**立即生效，不需要重开会话。

下拉框是空的或灰的，说明模型层没有返回配置列表——这时对话仍可正常进行，只是用默认人格。

## 5. 系统能力

### 5.1 托盘菜单

**托盘里只会有一个 Dounai 图标**（任务栏右下角）。

| 操作 | 效果 |
|---|---|
| 左键单击 | 显示 / 隐藏悬浮窗 |
| 左键双击 | 同上（避免误以为要双击） |
| 右键单击 | 弹出菜单 |

菜单项：

| 菜单项 | 作用 |
|---|---|
| 显示 / 隐藏 | 收起或展开悬浮窗（不退出进程） |
| 勿扰模式 | 静音、把 logo 变灰，并且不再主动弹窗 |
| 窗口置顶 | 关闭后悬浮窗可被其他窗口覆盖 |
| 退出 Dounai | 真正退出程序 |

#### 重复点击图标不会开出第二个 Dounai

Dounai 有**单实例保护**：再次双击图标时，不会启动新进程，
而是把已经在运行的那个窗口唤到最前面。

> 如果你见到**两个相同的 Dounai 图标**、其中一个点了没反应，那是旧版本的问题：
> 旧版没有单实例保护，重复启动会叠加出多个实例，每个实例占一个托盘图标。
> 升级到当前版本即可。
>
> 另外 Windows 11 会把不常用的图标收进「^」溢出区，找不到图标时点「^」展开，
> 或把图标拖到常驻区。

### 5.2 快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl + Alt + D` | 唤起 / 收起悬浮窗 |
| `Ctrl + Alt + Q` | 快速切换勿扰模式 |
| `Esc` | 收起对话面板 |

### 5.3 窗口行为

- **拖动窗口**：按住 logo 区域，或对话面板顶部标题栏的空白处，直接拖动即可移动窗口。
  按钮、输入框、下拉框不会触发拖动，可以正常点击。
- **置顶**：默认总在最前，可在托盘里关掉；
- **贴边吸附**：拖到屏幕边缘 24px 内会**在松手后**自动对齐。
  拖动过程中不会被拽回去，可以自由把窗口放到屏幕任意位置；
- **不占任务栏**：悬浮窗不出现在任务栏，只在托盘；
- **关闭即隐藏**：点右上角 × 只是收起，进程继续常驻。

> 小提示：光标移到可拖动区域会变成「移动」样式，据此可以判断哪里能拖。

## 6. 隐私说明（重要）

这是本产品的核心承诺，请认真读：

1. **对话内容不会被写进任何日志文件**。日志只记录状态、耗时、错误码，以及事件的 UUID。
2. **没有统计上报**。程序不包含任何遥测或分析代码，不会把你说了什么、用了多久发到任何服务器。
3. **不保存任何 API 密钥**。密钥只存在于模型层/语音层自己的环境变量里，悬浮窗从不读取。
4. **不会主动联网**。悬浮窗只连 `127.0.0.1` 上的三个本地服务。
   只有语音层按你选定的 TTS 厂商时，文本才会离开本机（这一点由语音层负责，并会写进它的诊断信息）。
5. **你的数据在你自己手里**。对话存档、记忆库都在上游模块的本地数据库里，可随时导出/删除。

> 想验证？用抓包工具观察：悬浮窗进程没有任何对外连接。

## 7. 设置

设置在本地存储（浏览器 `localStorage`），**不含任何密钥**：

| 项 | 说明 |
|---|---|
| 端点地址 | 三个上游的地址，默认 8101/8102/8103 |
| 形象渲染器 | 当前固定为 `logo`；后续会列出更多形象 |
| 默认模型 | 留空表示由模型层决定；填 `provider:model` 可指定 |
| 主题色 | 形象与强调色 |
| 勿扰 | 见 §4.1 |

---

## 8. 更换形象（进阶）

形象层与交互框架是解耦的。要换成正式助手形象：

1. 在 `src/avatar/renderers/` 新建一个文件，实现 `AvatarRenderer` 接口
   （`mount / setState / setEmotion / setSpeakingLevel / setTheme / unmount`）；
2. 在 `src/ui/main.ts` 里 `registerAvatar("your-id", () => new YourRenderer())`；
3. 把设置里的 `avatarRenderer` 改成 `your-id`。

**其他代码零改动**——编排器、状态机、音频驱动都不知道形象是什么样子。
接口定义见 `src/avatar/types.ts`，默认实现见 `src/avatar/renderers/logo.ts`。

## 9. 故障排查

### 9.1 悬浮窗显示「输入服务未连接」/「模型服务未连接」

这是**上游没起来**或**端口不对**，不是悬浮窗坏了。

> ⚠️ **先看这一条**：如果你用的是**打包后的桌面版**（`dounai.exe`），
> 而且「三个服务都确认在跑、`npm run dev` 打开也正常」——那很可能不是你的配置问题，
> 而是旧版本桌面端的一个已知缺陷。详见
> [事故说明](incident-desktop-connection.md)。
> 判断方法：重新 `git pull` 并重新打包，若恢复正常即属此列。

1. 逐个确认服务在跑：

```powershell
curl http://127.0.0.1:8101/healthz
curl http://127.0.0.1:8102/v1/healthz
curl http://127.0.0.1:8103/api/health
```

2. 如果三条都返回 200，但界面仍提示未连接，请检查端点设置里的地址与端口是否一致。
3. 注意：**输入层与模型层默认都用 8000**，很容易只起来一个。

### 9.2 有文字但没有语音

按顺序排查：

1. 语音层是否在跑（`curl http://127.0.0.1:8103/api/health`）；
2. 语音层的 TTS 厂商是否就绪：接口返回里 `providers[].ready` 为 `true`；
3. 该轮 `intent=tool`（工具结果）时**本来就不合成语音**，这是设计而非故障；
4. 界面会显示「语音暂不可用，本条只显示文字」——这说明文本链路正常，只是 TTS 降级了。

### 9.3 悬浮窗根本打不开（进程启动后立即退出）

在 Windows 上，悬浮窗依赖系统自带的 **WebView2 运行时**。若它损坏或被策略禁用，
程序无法启动。修复方式：

1. 下载并安装 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)（Evergreen 版）；
2. 或修复 Edge 浏览器（WebView2 随之修复）。

判断方法：运行 `msedgewebview2.exe --version`，若立即退出且无输出，即为该问题。

### 9.4 对话没有任何反应

1. 看托盘图标是否还在（进程是否被关掉）；
2. 按 `Ctrl + Alt + D` 唤起面板；
3. 看面板底部是否有橙色/红色提示条——它会说明是哪个环节失败；
4. 如果提示「还没有可用的模型」，说明模型层没有任何已配置的厂商密钥，
   需要在模型层填一个 API 密钥，或启用它自带的离线诊断模型。

## 10. 从源码运行

需要 Node ≥ 20 与 Rust ≥ 1.77（含 MSVC 工具链）。

```powershell
npm install

# 开发模式（带代理，自动转发到三个上游）
npm run dev

# 构建前端 + 打包桌面应用
npm run build
npx tauri build
```

测试：

```powershell
npm test          # 单元 + 集成测试
npm run typecheck # 类型检查
```

> 开发模式的代理会**移除 Origin 头**，这是有意为之——语音层会拒绝未列入白名单的
> 浏览器来源。原因与原理见 `docs/cors-and-proxy.md`。
